# 실험 명세 — 샤워 후 화장실 환기 알림 장치

> 이 문서는 팀 과제의 **실험 설계(계획서 v11 + 교수 피드백 반영)**를 코드/구현 기준으로 정리한 기록입니다.
> 주차별 작업은 각 PR에서 진행하고, 이 문서는 전체 명세의 단일 기준점(single source of truth)으로 유지합니다.

## 1. 한 문장 정의

샤워 후 환기(창문/환풍기)로 **습도가 충분히 낮아지면, "이제 닫아도/꺼도 된다"고 소리(부저)로 알려주는 장치**.

## 2. 동작 시나리오

```
1. 샤워 끝   → 습도 높음 ↑   → 사용자가 환기 시작 (창문 열기 / 환풍기 켜기)
2. 환기 중   → 습도 서서히 ↓
3. 습도 충분히 낮아짐 → 🔔 부저 알림 "환기 끝! 닫아도 됨"
4. 사용자가 창문 닫기 / 환풍기 끄기
```

- **조도센서**: 샤워 시작/화장실 사용 감지 → 습도 감시 모드를 켬 (환기 사이클의 시작점 판단)
- **습도센서**: 환기로 습도가 기준 이하로 떨어지는 시점 감지
- **부저**: 그 시점에 알림

> 조도센서를 떼면 "샤워가 언제 끝났는지(= 언제부터 습도를 지켜봐야 하는지)"를 판단하지 못한다.

## 3. 하드웨어

- **보드**: **Arduino UNO Q** — "듀얼 브레인" 보드
  - **STM32U585 MCU**: 실시간 센서 읽기/핀 제어 (아두이노 스케치, C++)
  - **Qualcomm QRB2210 + Debian 리눅스**: 보드에 내장, 파이썬 실행
- **GPIO 로직 전압**: **3.3V** (STM32 기준) → 계획서의 "3.3V 규칙"이 여기서 나옴
- 별도 PC 불필요 — 리눅스가 보드에 내장됨

| 부품 | 핀 | 방식 | 역할 |
|------|-----|------|------|
| DHT11 온습도 센서 모듈 | **D6** | 디지털 | 습도 측정 (핵심 판단) |
| 포토센서(CDS) + 10kΩ 전압분배 | **A2** | 아날로그 | 불 켜짐/꺼짐 → 샤워 시작·끝 |
| 부저 모듈 | **D8** | 디지털 출력 | 환기 완료 알림 |

> DHT11·포토센서·부저 모두 3.3V 로직에서 동작. 센서 전원은 3V3 핀에서 뽑는다.

### 핀 이름 표기 (교수 피드백 반영)
- 센서 지도 색("파란색 선/노란색 선")이 아니라 **핀 이름만** 사용: `DHT11 → D6`, `포토센서 → A2`.

## 4. 판단 로직 (상태 머신)

- **샘플링 주기**: 2초 (DHT11 최소 간격 1초 이상 + 샤워 급상승 60초 구간을 충분히 포착)
- **조도**: `light > 500` → 불 켜짐 (가짜 기준값, 11주차 실측으로 확정)
- **습도**:
  - 기준선 약 55% (가짜 값)
  - `기준선 + 15%p` 초과 → **샤워 중**
  - `기준선 + 5%p` 이내로 복귀 → **환기 완료**

```
대기(IDLE) ──불 켜짐 & 습도 급상승──▶ 샤워(SHOWER)
SHOWER ──불 꺼짐 / 습도 하강 시작──▶ 환기(VENTING)
VENTING ──습도 ≤ 기준선+5%p──▶ 완료(DONE) → 🔔 부저
DONE ──사용자 조치 후──▶ 대기(IDLE)
```

## 5. 시스템 구조 (UNO Q 한 보드 안에서)

```
        ┌───────────── Arduino UNO Q (한 보드) ─────────────┐
센서 ──▶ │ STM32 MCU (sketch.ino)      Qualcomm 리눅스 (main.py) │
DHT11 D6 │  - 2초마다 센서 읽기  ──notify──▶  - 상태 판단          │
포토 A2  │  - 부저 울리기        ◀──call────  - CSV 기록           │
부저     │          Bridge API (provide / notify / call)          │
        └───────────────────────────────────────────────────────┘
```

- **MCU (sketch.ino)**: 2초마다 DHT11·포토센서 읽어 `Bridge.notify`로 파이썬에 전달.
  부저 제어 함수를 `Bridge.provide_safe`로 노출해 파이썬이 `call`로 울림.
- **리눅스 (main.py)**: Bridge로 센서값 수신 → 상태 판단 → CSV 기록 → 환기 완료 시 부저 호출.
  기준선 기간엔 알림(부저 호출) off.
- **GPIO는 스케치(C++)로만 접근** — 파이썬은 핀 직접 제어 불가, Bridge 경유.
- Bridge 메시지는 MessagePack-RPC, 256바이트 제한.
- **CSV 헤더**: `time,humidity,temp,light,state,buzzer`

### 프로그래밍 방식 (Arduino App Lab + Bricks)
```
app/
├── sketch/sketch.ino    # STM32: 센서 읽기 + 부저
├── python/main.py       # 리눅스: 상태 판단 + CSV 기록
└── app.yaml             # Bricks: arduino:sketch + arduino:python
```
App Lab(또는 CLI)이 두 쪽을 함께 빌드·배포. 리눅스 쪽 통신은 `arduino-router` 서비스(UART) 경유.

## 6. 성공 기준

- CSV에서 `state`가 `VENT`로 바뀐 행부터 `humidity < 70`이 되는 행까지 행 수 × 2초 = 샤워 1회 고습 시간.
- 기간 전체 평균을 냄.
- **목표**: 고습 시간 평균을 기준선 대비 30% 감소 (기준선 측정 후 분 단위 확정).
- **기준선**: 같은 장치에서 부저 알림만 끄고 11주차부터 5일 측정.

## 7. 측정 계획

- **측정 기간**: 기준선 5일 + 설치 후 5일 *(v11의 ④ 여유주차 칸과 수치 불일치 → 5일로 통일 필요)*
- **측정 시간대**: 24시간 연속 기록, 분석은 샤워 종료 후 2시간 구간만.
- **설치 위치**: 샤워기 물이 직접 닿지 않는 벽면(센서), 문 근처 높은 곳(보드).
- **전원**: 화장실 밖 콘센트 + USB 충전기 + 2m USB-C 케이블.

## 8. 위험과 대안

| 위험 | 확인 시점 | 대안 |
|------|-----------|------|
| **DHT11이 샤워 직후 90% 근처에서 멈춤** (최우선 확인) | **9주차 모의 실험 첫 항목** — 밀폐통 분무 후 디지털 온습도계와 비교 | DHT22로 교체, 또는 판단 기준을 "최고점에서 내려가기 시작한 시점"으로 변경 |
| 낮 햇빛으로 포토센서 오판 | 11주차 기준선 기록 | 밝기 기준값 상향, 또는 습도 급상승만으로 샤워 판단 |
| 화장실 습기로 보드/센서 고장 | 11~12주차 설치 중 | 예비 DHT11 교체, 안 되면 모의실험 통 데이터로 시연 |
